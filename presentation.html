1. Introduction

What is the Student Performance Analytics Tool?

02

Our project is a Student Performance Analytics Tool developed using Core Java. It is a terminal-based application that helps teachers store marks, calculate percentages and grades automatically, rank students, and analyze class performance with zero manual errors.

1. STUDENT RECORD MANAGEMENT
  • Developed using object-oriented Java programming.
  • Helps teachers store student roll numbers and names easily.
  • Allows configuring custom academic subjects for any batch.
  • Keeps all student academic data structured in memory.
2. AUTOMATIC PERCENTAGE & GRADES
  • Automatically calculates total marks and percentages.
  • Assigns academic letter grades from A+ down to F.
  • Identifies each student's highest and lowest scoring subjects.
  • Eliminates human calculation mistakes completely.
3. STUDENT RANKING SYSTEM
  • Compares overall percentages of all students in the class.
  • Ranks students automatically from highest to lowest score.
  • Uses Java Comparator for objective, automated sorting.
  • Breaks ties alphabetically by student name.
4. PERFORMANCE ANALYTICS & REPORTS
  • Generates subject averages, top scores, and lowest scores.
  • Provides overall class performance summaries.
  • Shows total students passed, failed, and the class topper.
  • Saves all records in text files for permanent access.

6. Student Registration & Data Management

How Student Information is Collected, Validated, and Stored

07
1. INFORMATION COLLECTED
  • Roll Number: Unique integer identifier for each student.
  • Student Name: Clean string identifying the student.
  • Subject Names: Defined once during subject setup (e.g., Java, Math, DSA).
  • Subject Marks: Numerical scores entered for each subject.
2. DATA VALIDATION RULES
  • Duplicate Roll Check: The program scans existing records to ensure roll numbers are never repeated.
  • Marks Range Check (0–100): Uses custom InvalidMarksException to reject negative marks or values > 100.
  • Safe Input Loop: Re-prompts the user until valid inputs are provided without crashing.
3. DATA STRUCTURES USED
  • ArrayList<Student>: Dynamically stores all student objects in memory without fixed size limits.
  • HashMap<String, Integer>: Stores subject names as keys and marks as values for each student.
  • ArrayList<String>: Holds the list of registered academic subjects.

Key Explanation for Viva: "The program guarantees data integrity. Before adding a student, it checks whether the roll number already exists. While reading marks, if a value outside 0–100 is entered, the program catches our custom InvalidMarksException, displays an error message, and safely prompts the user again."

8. Student Ranking Using Comparator

Automated and Fair Merit List Generation

09
HOW JAVA COMPARATOR WORKS
  • Objective Ranking: Compares percentages of all students in the class.
  • Descending Order: Students with higher percentages receive higher ranks. Rank 1 is assigned to the top scorer.
  • Java Comparator Interface: Uses Comparator.comparingDouble(Student::getPercentage).reversed().
  • Name Tie-Breaker: If two students have identical percentages, their names are sorted alphabetically using .thenComparing(Student::getName).
  • Safe Clone: Ranking sorts a cloned ArrayList so original registration order is preserved.

HOW JAVA STREAM API IS USED
  • Class Average:
    students.stream().mapToDouble(Student::getPercentage).average()
  • Finding the Class Topper:
    students.stream().max(Comparator.comparingDouble(...))
  • Pass / Fail Counts:
    students.stream().filter(s -> !s.getGrade().equals("F")).count()
  • Grade Distribution:
    Collectors.groupingBy(Student::getGrade, TreeMap::new, ...)

11. File Handling & Backup System

Persistent Storage Architecture and Automated Byte-Stream Backup

12
DATA STORAGE (CHARACTER STREAMS)
  • File Used: students.txt
  • Saving Mechanism: Uses FileWriter and PrintWriter to write structured text lines to disk.
  • Loading Mechanism: Uses FileReader and BufferedReader to restore previous records upon startup.
  • Pipe-Delimited Storage Format:
    SUBJECTS|Java|Mathematics|DSA
    STUDENT|101|Tanmay Arora|85|90|75
  • Automatic Reload: Whenever the application is opened, loadData() parses the file and restores records into memory.
AUTOMATED BACKUP (BYTE STREAMS)
  • Backup File: students_backup.txt
  • Byte-Level Copy: Uses FileInputStream and FileOutputStream to read and write raw bytes.
  • Triggered by Option 8: Selecting Option 8 saves current data and immediately creates an exact backup clone.
  • Disaster Recovery: If students.txt is accidentally modified or deleted, the backup preserves student records.
  • Viva Distinction: Character streams handle human-readable text; Byte streams handle exact byte-by-byte file duplication.
